* CSRS ENT

CSRS ENT est le socle Python de l'ENT du CSRS. Il associe une interface Django/React à Odoo 19 Community sans dupliquer les modèles métier : Odoo conserve les comptes, l'organigramme, les tâches et leur historique; Django expose les pages, les API et la passerelle adaptées aux usages CSRS.

** État actuel

La préproduction fournit une interface React unique sous =/app/= pour les tâches, propositions, équipes, absences, missions, visites, agendas de direction et l'administration IT. Django porte les sessions, les contrats HTTP et la passerelle RPC centralisée; Odoo applique les autorisations et conserve seul les objets métier, leur historique, les événements d'audit et les PDF d'agenda versionnés.

La reprise des comptes, empreintes de mot de passe et relations actives de l'organigramme est explicite, simulable, auditée et idempotente. Les anciennes tâches, propositions, progressions et agendas restent consultables dans =csrs_report= comme historique et ne sont pas copiés dans CSRS ENT.

** Structure

- =apps/django/= : projet Django =csrs_ent=, sans ORM métier.
- =apps/django/gateway/= : frontière unique des appels Odoo.
- =apps/odoo/addons/csrs_reporting/= : extensions métier CSRS dans Odoo.
- =frontend/= : application React en TypeScript strict.
- =infrastructure/compose/= : stack Django, Odoo, PostgreSQL, Redis et Mailpit.
- =scripts/= : génération d'environnement, export en lecture seule, import Odoo et déploiement préprod.
- =docs/MANUAL.org= : guide utilisateur du premier lot CSRS ENT.
- =docs/architecture.md= : frontières et correspondance avec =csrs_report=.
- =DEV.org= : décisions, plan et état vérifié de la préproduction.

** Branches

- =dev= : intégration des changements.
- =preprod= : commit validé et déployé en préproduction.
- =prod= : production.

Les promotions suivent =dev= vers =preprod= puis =prod= sans réimplémenter le changement entre les branches.

** Démarrage local

#+begin_src sh
./scripts/bootstrap_env.sh .env
docker-compose --env-file .env -f infrastructure/compose/compose.yaml up --build
#+end_src

Django répond sur =http://127.0.0.1:18007/app/=, Odoo sur =http://127.0.0.1:18069/= et la boîte de capture Mailpit sur =http://127.0.0.1:18025/=. Les trois ports restent liés à l'interface locale. Les routes =/healthz/= et =/readyz/= distinguent la santé de Django de la disponibilité d'Odoo.

La première initialisation installe le module =csrs_reporting= et prépare l'administrateur Odoo. =./scripts/import_csrs_odoo.sh dry-run FICHIER_JSON .env= valide une reprise sans écriture; le mode =apply= l'exécute de façon réentrante. Les évolutions fonctionnelles continuent dans Odoo; Django ne devient pas une seconde base métier.

** Vérification

#+begin_src sh
PYENV_VERSION=csrs python apps/django/manage.py check
PYENV_VERSION=csrs pytest
PYENV_VERSION=csrs python -m ruff check apps/django
PYENV_VERSION=csrs mypy apps/django
npm run format:check --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
docker-compose --env-file .env.example -f infrastructure/compose/compose.yaml config --quiet
#+end_src

Cet hôte utilise =docker-compose= 1.29.2; =docker compose= peut remplacer la commande lorsqu'un greffon Compose v2 est disponible. Les contrôles de syntaxe Python, XML et Bash et les tests transactionnels Odoo complètent cette vérification.

** Préproduction

=./scripts/deploy_preprod.sh /srv/apps/csrs-ent-preprod/config/.env= valide Compose, reconstruit les images, met à niveau le module Odoo sans supprimer les volumes, puis démarre les services. =preprod.ent.koba.sarl= expose uniquement Django par Nginx; Odoo, Mailpit et PostgreSQL ne sont pas publiés sur Internet.

La préproduction de cet hôte utilise des versions immuables sous =/srv/apps/csrs-ent-preprod/releases/= et le lien =current= depuis la branche =preprod=. Sa cible publique est =https://preprod.ent.koba.sarl/=. Le fichier d'environnement reste hors des versions avec un mode d'accès restrictif.
