* Processus de demande et de prolongation de visa
#+begin_src plantuml :file Exports/processus_demande_prolongation_visa.png
  @startuml
  !pragma useVerticalIf on

  title Processus de demande et de prolongation de visa — proposition avec connecteurs

  ' =====================================================================
  ' MISE EN FORME
  ' =====================================================================
  skinparam shadowing false
  skinparam defaultFontSize 12
  skinparam ArrowColor #202020
  skinparam activityBackgroundColor #EEF0FB
  skinparam activityBorderColor #0078A8
  skinparam activityDiamondBackgroundColor #FFFDE1
  skinparam activityDiamondBorderColor #B3A500
  skinparam activityStartColor #DFFF80
  skinparam activityEndColor #FFCCCC
  skinparam swimlaneBorderColor #777777
  skinparam swimlaneTitleBackgroundColor #F7F7F7
  skinparam swimlaneTitleFontStyle bold

  ' =====================================================================
  ' CONNECTEURS
  '
  ' (S) : vérification et signature communes de la note préparée.
  ' (F) : convergence vers la disponibilité du visa ou de la prolongation.
  '
  ' « detach » termine uniquement la branche locale.
  ' Le traitement reprend au point portant le même identifiant.
  ' =====================================================================

  legend right
    |= Symbole |= Signification |
    | <color:#0000FF>**● S**</color> | Vérification et signature de la note préparée |
    | <color:#FF0000>**● F**</color> | Convergence vers la fin commune |
    | **●** | Début du processus : =start= |
    | **◉** | Fin du processus : =stop= |

    Toutes les occurrences d'un connecteur conservent
    la même lettre, la même couleur et le même cercle.
    Le sens du renvoi est indiqué par les flèches.
    Une note « POINT DE REPRISE » identifie l'arrivée.
  endlegend

  |Chercheur / Visiteur|
  start

  if (Type de demande ?) then (Visa avant l'arrivée)
    :Envoyer un courriel à la Direction;
    note right
      Préciser :
      - date d'arrivée ;
      - date de départ ;
      - but du voyage ou de la mission.

      Joindre une copie du passeport.
    end note

    |Assistante DRD / DRV|
    :Rédiger la lettre de demande\nde visa de séjour;
    note right
      Lettre destinée à l'Ambassade
      de Côte d'Ivoire du pays
      de résidence du visiteur.

      Délai indicatif : 24 h.
    end note
    #blue:(S)
    detach
  else (Prolongation pendant le séjour)
    |Assistante DRD / DRV|
    :Rédiger la demande\nde prolongation de visa;
    note right
      Préciser la période
      de prolongation sollicitée.

      Le formulaire doit idéalement
      être disponible deux semaines
      avant l'expiration du visa.
    end note
    #blue:(S)
    detach
  endif

  ' 1. VÉRIFICATION ET SIGNATURE COMMUNES
  |Chef de service I2A|
  #blue:(S)
  note right
    POINT DE REPRISE S
    La vérification de la note préparée
    reprend ici.
  end note
  :Vérifier la note verbale\nou la note de prolongation;
  note right
    Pour une prolongation :
    délai indicatif de 24 h.
  end note

  |Directeur Général|
  :Signer la note verbale;
  :Transmettre la note signée\nau secrétariat;

  ' 2. TRAITEMENT PROPRE AU TYPE DE DEMANDE
  if (Type de demande ?) then (Visa avant l'arrivée)
    |Assistante DRD / DRV|
    :Scanner la note verbale signée;
    :Envoyer la note scannée\nau chercheur ou au visiteur;

    |Chercheur / Visiteur|
    :Recevoir la note verbale scannée;
    #red:(F)
    detach
  else (Prolongation pendant le séjour)
    |Assistante DRD / DRV|
    :Préparer le dossier\nde prolongation;
    note right
      Pièces du dossier :
      - note verbale signée ;
      - deux photos d'identité ;
      - formulaire de prolongation ;
      - copie de la première page
        du passeport ;
      - copie du visa expiré,
        en cours ou antérieur ;
      - passeport original.
    end note
    :Transmettre le dossier\nau coursier;

    |Coursier|
    :Déposer le dossier au MAE;
    note right
      Dépôt pendant un jour de course.
      Objectif : transmission du dossier
      au MAE dans les 48 h.
    end note
    :Déposer la décharge\nau secrétariat;

    |Assistante / Secrétariat|
    :Recevoir et enregistrer\nla décharge;

    |Ministère des Affaires étrangères|
    :Traiter la demande\nde prolongation;
    note right
      Délai indicatif :
      15 à 30 jours.
    end note

    |Assistante / Secrétariat|
    :Assurer le suivi du dossier\nauprès du MAE;
    :Appeler le coursier pour\nla récupération du passeport;

    |Coursier|
    :Retirer le passeport\navec le visa prolongé;
    :Transmettre le passeport\nau secrétariat;

    |Assistante / Secrétariat|
    :Réceptionner le passeport\navec le visa;
    :Transmettre le passeport\nau chercheur ou au coordonnateur;

    |Chercheur / Visiteur|
    :Recevoir le passeport\navec le visa prolongé;
    #red:(F)
    detach
  endif

  ' 3. FIN COMMUNE
  |Chercheur / Visiteur|
  #red:(F)
  note right
    POINT DE REPRISE F
    Les deux types de demande
    rejoignent la fin ici.
  end note
  :Visa ou prolongation disponible;
  stop
  @enduml
#+end_src

* Processus d'élaboration des ordres de mission
#+begin_src plantuml :file Exports/processus_elaboration_ordres_mission.png
  @startuml
  !pragma useVerticalIf on

  title Processus d'élaboration des ordres de mission — proposition avec connecteurs

  ' =====================================================================
  ' MISE EN FORME
  ' =====================================================================
  skinparam shadowing false
  skinparam defaultFontSize 12
  skinparam ArrowColor #202020
  skinparam activityBackgroundColor #EEF0FB
  skinparam activityBorderColor #0078A8
  skinparam activityDiamondBackgroundColor #FFFDE1
  skinparam activityDiamondBorderColor #B3A500
  skinparam activityStartColor #DFFF80
  skinparam activityEndColor #FFCCCC
  skinparam swimlaneBorderColor #777777
  skinparam swimlaneTitleBackgroundColor #F7F7F7
  skinparam swimlaneTitleFontStyle bold

  ' =====================================================================
  ' CONNECTEURS
  '
  ' (S) : circuit commun de signature et de distribution.
  ' (F) : convergence après le traitement éventuel par le parc automobile.
  '
  ' « detach » termine uniquement la branche locale.
  ' Le traitement reprend au point portant le même identifiant.
  ' =====================================================================

  legend right
    |= Symbole |= Signification |
    | <color:#0000FF>**● S**</color> | Signature et distribution de l'ordre préparé |
    | <color:#FF0000>**● F**</color> | Convergence après le traitement du parc automobile |
    | **●** | Début du processus : =start= |
    | **◉** | Fin du processus : =stop= |

    Toutes les occurrences d'un connecteur conservent
    la même lettre, la même couleur et le même cercle.
    Le sens du renvoi est indiqué par les flèches.
    Une note « POINT DE REPRISE » identifie l'arrivée.
  endlegend

  |Chercheur / Employé|
  start
  :Identifier un besoin de déplacement\nhors de la ville d'Abidjan;
  note right
    L'ordre de mission est nécessaire
    pour un déplacement par véhicule
    ou par avion.
  end note
  :Initier la demande\nd'ordre de mission;

  if (Mission à l'intérieur du pays ?) then (Oui)
    :Transmettre à l'assistante les TDR\net, au besoin, la lettre d'invitation;
    note right
      Délai indicatif : 24 h
    end note

    |Assistante / Secrétariat|
    :Préparer l'ordre de mission intérieure;
    note right
      Informations principales :
      - Numéro de l'ordre de mission
      - Participants et fonctions
      - Lieu et motif
      - Itinéraire
      - Véhicule et immatriculation
      - Dates de départ et de retour
      - Prise en charge

      Délai indicatif : 24 h
    end note
    #blue:(S)
    detach
  else (Non, mission extérieure)
    |Chercheur / Employé|
    :Transmettre au secrétariat les TDR,\nla lettre d'invitation éventuelle\net le billet d'avion;
    note right
      Délai indicatif : 24 h
    end note

    |Assistante / Secrétariat|
    :Préparer le projet\nd'ordre de mission extérieure;
    note right
      Informations principales :
      - Numéro de l'ordre de mission
      - Nom et fonction du voyageur
      - Lieu, motif et destination
      - Moyen de transport ou compagnie
      - Dates de départ et de retour
      - Prise en charge

      Délai indicatif : 24 à 48 h
    end note
    #blue:(S)
    detach
  endif

  ' 1. SIGNATURE ET DISTRIBUTION COMMUNES
  |Assistante / Secrétariat|
  #blue:(S)
  note right
    POINT DE REPRISE S
    Le circuit commun de signature
    reprend ici.
  end note
  :Transmettre l'ordre de mission\nau Directeur Général;

  |Directeur Général|
  :S'assurer de l'utilité\nde la mission;
  :Signer l'ordre de mission;
  :Transmettre l'ordre signé\nau secrétariat;
  note right
    Transmission immédiate
    après signature.
  end note

  |Assistante / Secrétariat|
  :Réceptionner l'ordre\nde mission signé;
  :Transmettre une copie\nà la comptabilité;

  |Comptabilité|
  :Recevoir la copie\nde l'ordre de mission;

  |Assistante / Secrétariat|
  :Transmettre l'original\nau demandeur;

  |Chercheur / Employé|
  :Recevoir l'ordre\nde mission signé;

  |Assistante / Secrétariat|
  :Classer une copie\nde l'ordre de mission;
  if (Parc automobile concerné ?) then (Oui)
    :Transmettre l'ordre de mission\nau parc automobile;

    |Parc automobile|
    :Recevoir l'ordre de mission;
    :Préparer le véhicule\nsi nécessaire;
    #red:(F)
    detach
  else (Non)
    |Assistante / Secrétariat|
    :Poursuivre sans transmission\nau parc automobile;
    #red:(F)
    detach
  endif

  ' 2. FIN COMMUNE
  |Chercheur / Employé|
  #red:(F)
  note right
    POINT DE REPRISE F
    Les traitements avec ou sans parc
    automobile rejoignent la fin ici.
  end note
  :Ordre de mission disponible\npour le déplacement;
  stop
  @enduml
#+end_src

* Processus d'élaboration du Bon de sortie de fonds (BSF)
#+begin_src plantuml :file Exports/processus_elaboration_bsf.png
  @startuml
  !pragma useVerticalIf on

  title Processus d'élaboration du Bon de Sortie de Fonds — proposition avec connecteurs

  ' =====================================================================
  ' MISE EN FORME
  ' =====================================================================
  skinparam shadowing false
  skinparam defaultFontSize 12
  skinparam ArrowColor #202020
  skinparam activityBackgroundColor #EEF0FB
  skinparam activityBorderColor #0078A8
  skinparam activityDiamondBackgroundColor #FFFDE1
  skinparam activityDiamondBorderColor #B3A500
  skinparam activityStartColor #DFFF80
  skinparam activityEndColor #FFCCCC
  skinparam swimlaneBorderColor #777777
  skinparam swimlaneTitleBackgroundColor #F7F7F7
  skinparam swimlaneTitleFontStyle bold

  ' =====================================================================
  ' CONNECTEURS
  '
  ' (D) : saisie initiale ou correction d'une demande non conforme.
  ' (C) : traitement commun des corrections du BSF.
  ' (G) : transmission initiale ou renouvelée au DG.
  ' (P) : paiement commun après préparation des espèces ou du chèque.
  '
  ' « detach » termine uniquement la branche locale.
  ' Le traitement reprend au point portant le même identifiant.
  ' =====================================================================

  legend right
    |= Symbole |= Signification |
    | <color:#008080>**● D**</color> | Saisie initiale ou correction de la demande |
    | <color:#FFA500>**● C**</color> | Traitement commun des corrections du BSF |
    | <color:#008000>**● G**</color> | Transmission ou retransmission au DG |
    | <color:#800080>**● P**</color> | Paiement après préparation des espèces ou du chèque |
    | **●** | Début du processus : =start= |
    | **◉** | Fin du processus : =stop= |

    Toutes les occurrences d'un connecteur conservent
    la même lettre, la même couleur et le même cercle.
    Le sens du renvoi est indiqué par les flèches.
    Une note « POINT DE REPRISE » identifie l'arrivée.
  endlegend

  |dem| Employé / Chercheur
  start
  :Identifier un besoin de fonds;

  ' 1. DEMANDE INITIALE OU CORRIGÉE
  #teal:(D)
  note right
    POINT DE REPRISE D
    La saisie ou la correction
    de la demande reprend ici.
  end note
  :Exprimer ou corriger\nla demande de fonds;
  note right
    Informations à préciser :
    - Projet ou service
    - Ligne budgétaire
    - Objet du décaissement
    - Montant demandé
    - Initiateur
    - Bénéficiaire

    Documents possibles :
    - Ordre de mission
    - TDR
    - Budget
    - Contrat
    - Convention
    - Facture
    - Demande d'achat
  end note

  |sfc| Service Finances-Comptabilité
  :Recevoir la demande\net les pièces justificatives;
  :Vérifier la capacité budgétaire\ndu projet ou du service;
  :Vérifier la situation comptable\nde l'initiateur;
  if (Demande conforme ?) then (Oui)
    |sfc|
    :Élaborer le Bon de Sortie\nde Fonds;
    note right
      Jours d'élaboration du BSF :
      - lundi
      - mercredi
    end note
  else (Non)
    |dem|
    -> Demande à corriger;
    #teal:(D)
    detach
  endif

  ' 2. CIRCUIT INITIAL DE VISA
  |dem|
  :Vérifier et viser le BSF;

  |chef| Chef de Service FC
  :Contrôler et viser le BSF;

  |daf| Direction Administrative et Financière
  :Vérifier et viser le BSF;

  |cpt| Comptable en charge du projet
  :Contrôler le dossier financier;
  if (Dossier financier conforme ?) then (Oui)
    #green:(G)
    detach
  else (Non)
    :Demander la correction du BSF;
    #orange:(C)
    detach
  endif

  ' 3. TRAITEMENT COMMUN DES CORRECTIONS
  |chef|
  #orange:(C)
  note right
    POINT DE REPRISE C
    Les corrections demandées après
    le contrôle comptable ou par le DG
    rejoignent ce traitement unique.
  end note
  :Corriger le BSF;
  :Viser à nouveau le BSF;

  |daf|
  :Vérifier et viser\nle BSF corrigé;

  |cpt|
  :Contrôler le dossier corrigé;
  if (Dossier corrigé conforme ?) then (Oui)
    #green:(G)
    detach
  else (Non)
    :Demander une nouvelle correction;
    #orange:(C)
    detach
  endif

  ' 4. EXAMEN INITIAL OU RENOUVELÉ PAR LE DG
  |cpt|
  #green:(G)
  note right
    POINT DE REPRISE G
    Tout dossier conforme est transmis
    ou retransmis au DG à partir d'ici.
  end note
  :Transmettre le BSF au DG;

  |dg| Directeur Général
  :Examiner le Bon de Sortie\nde Fonds;
  if (BSF conforme pour approbation ?) then (Oui)
    :Approuver et signer le BSF;
    note right
      Seule la signature du DG
      autorise le paiement du BSF.
    end note
  else (Non)
    :Demander la correction du BSF;
    #orange:(C)
    detach
  endif

  ' 5. PRÉPARATION ET PAIEMENT
  |cpt|
  :Recevoir le BSF\nsigné et validé;
  :Transmettre le BSF\nà la caisse;

  |caisse| Caisse
  :Réceptionner le BSF\nsigné et approuvé;
  if (Montant inférieur ou égal à\n200 000 F CFA ?) then (Oui)
    :Préparer le paiement\nen espèces;
    #purple:(P)
    detach
  else (Non)
    :Préparer le paiement\npar chèque;
    :Informer le demandeur\nde la disponibilité du chèque;
    #purple:(P)
    detach
  endif

  #purple:(P)
  note right
    POINT DE REPRISE P
    Les deux modes de préparation
    rejoignent le paiement ici.
  end note
  :Effectuer le paiement;
  note right
    Jours de caisse :
    - mardi
    - jeudi
    - vendredi

    Délai prévu :
    au plus tard 3 jours
    après la demande.
  end note

  |ben| Bénéficiaire
  :Recevoir les espèces\nou le chèque;
  stop
  @enduml
#+end_src

* Processus de gestion des données

#+begin_src plantuml :file Exports/processus_gestion_donnees.png
  @startuml
  !pragma useVerticalIf on

  title Processus de gestion des données — proposition avec connecteurs

  ' =====================================================================
  ' MISE EN FORME
  ' =====================================================================
  skinparam shadowing false
  skinparam defaultFontSize 12
  skinparam ArrowColor #202020

  skinparam activityBackgroundColor #EEF0FB
  skinparam activityBorderColor #0078A8
  skinparam activityDiamondBackgroundColor #FFFDE1
  skinparam activityDiamondBorderColor #B3A500
  skinparam activityStartColor #DFFF80
  skinparam activityEndColor #FFCCCC

  skinparam swimlaneBorderColor #777777
  skinparam swimlaneTitleBackgroundColor #F7F7F7
  skinparam swimlaneTitleFontStyle bold

  ' =====================================================================
  ' CONNECTEURS
  '
  ' (T) : transfert unique, initial ou après correction de la collecte.
  ' (S) : validation unique des systèmes, initiale ou après correction.
  ' (Q) : contrôle qualité unique, initial ou après correction.
  ' (A) : entrée unique de l'audit après partage ou action corrective.
  ' (F) : convergence de la suppression et de la prolongation.
  '
  ' « detach » termine uniquement la branche locale.
  ' Le traitement reprend au point portant le même identifiant.
  ' =====================================================================

  legend right
    |= Symbole |= Signification |
    | <color:#008080>**● T**</color> | Transfert initial ou après correction de la collecte |
    | <color:#0000FF>**● S**</color> | Validation initiale ou après correction des systèmes |
    | <color:#FFA500>**● Q**</color> | Contrôle qualité initial ou après correction |
    | <color:#800080>**● A**</color> | Convergence vers l'audit ou reprise de l'audit |
    | <color:#FF0000>**● F**</color> | Convergence vers la fin commune |
    | **●** | Début du processus : =start= |
    | **◉** | Fin du processus : =stop= |

    Toutes les occurrences d'un connecteur conservent
    la même lettre, la même couleur et le même cercle.
    Le sens du renvoi est indiqué par les flèches.
    Une note « POINT DE REPRISE » identifie l'arrivée.
  endlegend

  ' 1. PLANIFICATION
  |Directeur d'étude|
  start
  :Définir les objectifs et les besoins\nen données de l'étude;

  |Gestionnaire de données|
  :Élaborer ou adapter le Plan\nde Gestion des Données (PGD);
  note right
    Le PGD couvre :
    - acquisition et transfert ;
    - traitement et analyse ;
    - stockage et sauvegarde ;
    - accès et partage ;
    - archivage et suppression.
  end note

  ' 2. VALIDATION DES SYSTÈMES
  |Administrateur système / TSI|
  #blue:(S)
  note right
    POINT DE REPRISE S
    La validation reprend ici.
  end note
  :Valider le matériel, les logiciels\net les systèmes informatiques;
  if (Systèmes validés ?) then (Non)
    :Corriger la configuration\nou les anomalies;
    -> Configuration corrigée;
    #blue:(S)
    detach
  else (Oui)
    ' Les systèmes validés permettent de poursuivre le processus.
  endif

  |Responsable Assurance Qualité|
  :Vérifier la version correcte de la POS\net former le personnel;

  ' 3. COLLECTE ET TRAITEMENT
  |Chercheur / Employé|
  :Collecter les données avec\ndes instruments validés;
  note right
    Assurer la traçabilité :
    - date et heure ;
    - collecteur ;
    - source ;
    - déviations éventuelles.

    Utiliser le contrôle visuel
    et la double saisie si nécessaire.
  end note

  |Gestionnaire de données|
  #teal:(T)
  note right
    POINT DE REPRISE T
    Le transfert reprend ici.
  end note
  :Transférer les données par un canal sécurisé\net vérifier leur intégrité;
  :Nettoyer, transformer\net intégrer les données;
  :Analyser les données\navec des outils validés;
  note right
    Exemples d'outils :
    Excel, Stata, Python
    ou logiciels spécifiques BPL.
  end note

  ' 4. CONTRÔLE QUALITÉ FACTORISÉ
  #orange:(Q)
  note right
    POINT DE REPRISE Q
    Le contrôle qualité reprend ici.
  end note
  :Effectuer le contrôle qualité\net valider les résultats;
  if (Données conformes ?) then (Non)
    if (Collecte correcte ?) then (Oui)
      |Gestionnaire de données|
      :Corriger le nettoyage,\nle traitement ou l'analyse;
      -> Traitement corrigé;
      #orange:(Q)
      detach
    else (Non)
      |Chercheur / Employé|
      :Corriger ou reprendre\nla collecte des données;
      -> Données corrigées;
      #teal:(T)
      detach
    endif
  else (Oui)
    ' Les données conformes peuvent être stockées.
  endif

  ' 5. STOCKAGE ET PARTAGE ÉVENTUEL
  |Administrateur système / TSI|
  :Stocker les données\nde manière sécurisée;
  :Effectuer les sauvegardes\net tester la restauration;

  |Gestionnaire de données|
  if (Accès ou partage requis ?) then (Oui)
    |Chercheur / Employé|
    :Soumettre une demande d'accès;
    note right
      La demande précise :
      - l'identité ;
      - la justification ;
      - les données concernées ;
      - le niveau d'accès souhaité.
    end note

    |Gestionnaire de données|
    :Examiner la demande d'accès;
    if (Accès approuvé ?) then (Oui)
      |Administrateur système / TSI|
      :Attribuer les droits appropriés\nselon le moindre privilège;

      |Gestionnaire de données|
      :Partager les données par un canal sécurisé\net journaliser le partage;
      #purple:(A)
      detach
    else (Non)
      :Documenter le refus d'accès;
      #purple:(A)
      detach
    endif
  else (Non)
    :Poursuivre sans partage externe;
    #purple:(A)
    detach
  endif

  ' 6. AUDIT FACTORISÉ
  |Responsable Assurance Qualité|
  #purple:(A)
  note right
    POINT DE REPRISE A
    Les issues du partage et les actions
    correctives rejoignent l'audit ici.
  end note
  :Auditer la conformité, la sécurité\net la traçabilité;
  if (Audit conforme ?) then (Oui)
    ' Un audit conforme permet de préparer l'archivage.
  else (Non)
    |Gestionnaire de données|
    :Mettre en œuvre les actions correctives\navec le service TSI;
    -> Actions correctives terminées;
    #purple:(A)
    detach
  endif

  ' 7. ARCHIVAGE ET CONSERVATION
  |Gestionnaire de données|
  :Clôturer l'usage actif des données\net préparer l'archivage;

  |Documentation et Archives|
  :Archiver les données\net documenter les métadonnées;
  :Conserver les données pendant\nla durée réglementaire applicable;
  note right
    Le document mentionne une échéance
    de cinq ans après la fin de l'étude,
    sous réserve d'obligations de
    conservation plus longues.
  end note

  |Directeur d'étude|

          detach
        case (Rejet)

          stop;  
        case (DA signée)
          :DA approuvée;
          #green:(A)
          detach

  '

  '   - le dépôt de la facture
